# r4sGate + Lotus Lantern: интеграция для ESP32 (исходный проект)

## Важный статус

Это **модифицированные исходники**, а не проверенный `.bin`. Из-за отсутствия ESP-IDF и ESP32 здесь нельзя подтвердить итоговую прошивку на железе. До сборки в ESP-IDF 5.4.2 **ничего не загружать на ESP32**. После сборки проверять сначала на резервной плате, желательно с сохранением исходного образа и NVS.

## Что сделано

- Добавлена отдельная регистрация Bluedroid GATTC `app_id=5`, с независимым `FFF0/FFF3` драйвером и BLE-подключением по запросу; существующие пять Redmond-профилей не переименовывались.
- Используется прежний сканер r4sGate; четыре уже настроенных ATC/PVVX-термометра должны продолжать обрабатываться через BLE Monitor.
- До 5 MAC-адресов в отдельном пространстве NVS `lotus` (`mac0`..`mac4`). В первом слоте по умолчанию стоит проверенная пользователем `BE:37:FA:00:7F:F2`. Остальные слоты изначально пустые.
- Веб-страница `http://<IP-ESP32>/lotus`: записывает MAC-адреса, проверяет формат/дубли, сохраняет и перезапускает шлюз. Защищена существующей веб-авторизацией r4sGate.
- MQTT Discovery Home Assistant: отдельный светильник на каждый заполненный слот. Команды JSON Light: питание, RGB, яркость. Отчёт о состоянии **предполагаемый (assumed state)** после принятой стэком отправки, а не подтверждение самой ленты.
- BLE-драйвер последовательно подключается к доступным лентам, использует WRITE NO RESPONSE и закрывает соединение после отправки. Реализованы таймауты и задержка повторов после ошибок.

## Проверенные пользователем BLE-команды

ELK-BLEDOM, `BE:37:FA:00:7F:F2`, сервис `FFF0`, характеристика `FFF3`, WRITE NO RESPONSE:

- ON: `7E0004F00001FF00EF`
- OFF: `7E0004000000FF00EF`
- RGB красный: `7E000503FF000000EF`
- Яркость 20%: `7E00011400000000EF`

Устройство `ELK-BLEDDM`, `BE:27:32:01:5D:51`, пока **не проверено командами**: пока не добавляйте его во второй слот. Не все Lotus Lantern используют один протокол.

## Сборка с ESP-IDF 5.4.2

Исходная конфигурация в `sdkconfig` предназначена для **ESP32, 4 MB Flash**, с разделами OTA по `0x1E0000` (1 966 080 байт). **НЕ** прошивать этот проект на C3/S3 без отдельной корректной сборки.

1. Установить ESP-IDF **5.4.2**, открыть его терминал, перейти в корень проекта.
2. Запустить `idf.py build`.
3. Только при **успешной** сборке и размере файла `build/r4sGate.bin <= 1966080` появляется кандидат на OTA-прошивку.
4. Сначала проверить сборку на запасном ESP32 с той же конфигурацией флеш-памяти, логами по UART, Wi-Fi, BLE Monitor и MQTT.
5. После успешного теста можно рассматривать обновление штатного устройства через веб-страницу **Load firmware**, имея оригинальный `.bin` для возврата.

### Альтернативная облачная сборка

В архив включён `.github/workflows/build-lotus.yml`. Поместите содержимое архива в **собственный GitHub-репозиторий**, запустите в GitHub `Actions` → `Build r4sGate Lotus (ESP32)` → `Run workflow`. При успешной сборке GitHub выдаст артефакт `r4sGate-Lotus-ESP32-OTA` с файлом `r4sGate.bin`. При ошибке откройте журнал компиляции. В текущей среде этот workflow не запускался и его успех не гарантирован.

## Home Assistant

После соединения с MQTT сработает Discovery `homeassistant/light/r4sgate_lotus_<MAC>/config` и подписка `r4s/lotus/<MAC>/set` (точный префикс — `MQTT_BASE_TOPIC`, заданный в r4sGate). Пример:

```json
{"state":"ON","brightness":128,"color":{"r":255,"g":120,"b":20}}
```

Отдельные ленты можно добавлять и убирать через `/lotus` без пересборки. После смены MAC старые retained Discovery-конфигурации в брокере MQTT могут потребовать ручной очистки, если они больше не нужны.

## Что осталось непроверенным

- Сборка ESP-IDF / размер приложения / OTA в реальном окружении.
- Фактический BLE-коннект и запись с ESP32; нRF Connect на телефоне уже подтвердил команды, но это не тест BLE на ESP32.
- Одновременная работа пяти лент и отсутствие пропусков сообщений от четырёх PVVX-термометров.
- Типы Bluetooth-адресов у будущих лент, качество связи (первая лента показывала около −90 dBm).
- Восстановление управления при постоянной потере питания и переподключении, очистка старых retained Discovery.

Библиотечные MQTT и протокольные тесты проведены на хостовой машине; это **не** тест прошивки в устройстве.

### Локальные протокольные и имитационные тесты

`sh tests/lotus_host/run.sh` на Linux с установленным `libcjson.so.1` и GCC. Эти тесты моделируют API Bluedroid/HTTP/NVS/MQTT, не заменяют реальную сборку ESP-IDF и проверку радиосвязи.

**В архиве намеренно удалены готовые `.bin` из исходного репозитория**, потому что они не содержат нашу доработку и их легко перепутать с новым обновлением.
